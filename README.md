# pipelinek-acp

Reactive Agentic Pipelines for [PipelineK](https://github.com/Rubentxu/pipeline-kotlin): an ACP-client plugin that lets a Kotlin pipeline drive an external agent over the Agent Client Protocol, react to typed agent events, and expose its own steps as MCP tools.

- Backlog (autoridad única, living in [pipelinek-home](https://github.com/Rubentxu/pipelinek-home)): filter tasks by label `repo:pipelinek-acp`; SDK contracts carry `repo:pipeline-kotlin`.
- Status: the plugin ships five steps — `acpPrompt` (one delegation), `acpTask` (an isolated delegation under a profile), `acpSession` (a composed session: several sequential turns plus the negotiated session operations), `acpReactive` (one delegation that reacts to the agent's updates by dispatching its body's reaction slot, once per update, each with its own durable identity) and `acpReaction` (the body child it dispatches). The intake tasks are on the home board; the work is tracked there.
- Human interaction: the steps that can be asked by the agent for a person's input declare the human-decision capability and put the question to a person through the port the published SDK carries; the person's answer reaches the agent and grants nothing — a permission is still the declared authority's to decide.
- Observability (SDK contract PKACP-SDK-04): `acpPrompt`, `acpSession` and `acpTask` project typed ACP facts (`pipelinek.acp.*`) into PipelineK's observability through the published seam — an `EventDefinitionContributor` contributes the manifest's kinds and the `plugin.event-emission` capability emits them; never the wire's JSON-RPC. The payload is redacted field by field under a whitelist (no `rawInput`, no `rawOutput`, no `_meta`, no raw JSON of an unknown variant; URIs are reduced to scheme/host/path — no userinfo, query or fragment; text is clipped and the clip is marked) and the lane is bounded: control facts survive a chunk avalanche and every telemetry loss is counted in an `observation_gap`. The lifecycle facts the plugin establishes itself are published from the real exchange path — `exchange_started` once the negotiation held, `turn_ended` per turn with the agent's stop reason, `exchange_cancelled` when the budget or the engine cuts the exchange (said together with the `session/cancel` the agent receives), `exchange_refused` with the typed refusal's kindToken — and the task e2e row (`scripts/e2e-acp-task.sh`, LIFECYCLE) measures all four against the durable events table, the cancelled one under a deliberate chunk avalanche. Reverse-leg notifications the SDK delivers outside the prompt stream reach the same projection, without giving up their journal row.

CI is PipelineK running locally (`pipeline.kts`), not GitHub Actions.
